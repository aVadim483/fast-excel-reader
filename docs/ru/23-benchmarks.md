# Замеры ресурсов ридера

[English](../23-benchmarks.md)

Запускайте каждый вход в отдельном процессе PHP:

```sh
php -d xdebug.mode=off tools/benchmark-reader.php tests/test_files/ods/family.ods --string
php -d xdebug.mode=off tools/benchmark-reader.php demo/files/demo-100k-rows.xlsx --string
```

`--string` включает копирование всего файла, используемое в `openString()`.
Без него файл открывается напрямую. Результат разделяет открытие и чтение,
пики памяти PHP, выборочные замеры временного диска и диск после `close()`.
Память аллокатора PHP — не RSS процесса. Время чтения включает измерение диска;
это диагностика, а не сравнение с другими библиотеками. Итератор не сохраняет строки.

Локальные результаты 2026-11-13: Windows, PHP 8.4.19, Xdebug отключён, отдельный
процесс для каждого входа, `--string`:

| Вход | Строк / ячеек | Пик памяти PHP | Временный диск после close |
|---|---|---|---|
| Excel family.xlsx | 4 / 10 | 2 МиБ | 0 байт |
| Excel family.ods | 4 / 9 | 2 МиБ | 0 байт |
| BIFF8 demo-00-test.xls | 22 / 45 | 2 МиБ | 0 байт |
| test.csv | 3 / 9 | 2 МиБ | 0 байт |
| ODS: 1 000 000 пустых повторяющихся строк, затем значение | Выдано 1 / 1 | 2 МиБ | 0 байт |
| demo-100k-rows.xlsx | 100 000 / 500 000 | 6 МиБ | 0 байт |

В случае ODS каждая повторяющаяся строка содержит 16 384 пустые ячейки;
строки и ячейки не материализуются. Случай воспроизводится тестом повторов OdsReaderTest.
Фикстуры family отличаются пустой покрытой ячейкой, опущенной Excel в ODS.
Остальные входы содержат разные данные: результаты не доказывают преимущество
формата по скорости или памяти. На других книгах объём общих строк, изображений
и ширина выбранной строки могут определять потребление памяти. Дискового SST-кэша пока нет.
