# История изменений

[🇬🇧 English](CHANGELOG.md) · 🇷🇺 Русский

Здесь документируются все значимые изменения проекта.

Файл начинается с версии 3.2.0; более раннюю историю смотрите на
[странице релизов](https://github.com/aVadim483/fast-excel-reader/releases).

## 4.4.0

### Добавлено

* **Открытие книги из строки или потока.** `Excel::openString($content)` читает книгу, находящуюся в
  памяти (BLOB из базы, тело HTTP-ответа, чтение из S3/Flysystem), а `Excel::openStream($stream)` —
  из открытого потока (URL через `fopen()`, `php://memory`, поток чтения Flysystem). Оба выбирают
  ридер по сигнатуре, ровно как `open()`, поэтому строка/поток с XLSX, XLS или CSV читаются так же,
  как тот же файл с диска, и принимают те же `$options`, что и `open()`. Содержимое копируется во
  временный файл (с учётом `Excel::setTempDir()`), который удаляется при завершении скрипта; поток,
  переданный в `openStream()`, не закрывается. См.
  [docs/ru/10-getting-started.md](docs/ru/10-getting-started.md).
* **Чтение гиперссылок ячеек.** `Sheet::getHyperlinks()` возвращает гиперссылки листа с ключами по
  ячейке (или диапазону), к которой они привязаны, каждая в виде `['link' => ..., 'location' => ...,
  'display' => ..., 'tooltip' => ...]`. Внешние цели разрешаются из файла связей листа; внутренние
  ссылки отдают своё местоположение `location` внутри документа. Лист без гиперссылок возвращает
  пустой массив. См. [docs/ru/16-sheet-metadata.md](docs/ru/16-sheet-metadata.md).

## 4.3.0

### Изменено

* Пустой (нулевого размера) файл, переданный в `Excel::open()`, теперь сразу падает с понятной ошибкой
  «File ... is empty», а не открывается молча как CSV из нуля строк: `open()` определяет формат по
  сигнатуре, а пустой файл не совпадает ни с одной. `Excel::openCsv()` не изменён и по-прежнему читает
  пустой файл как валидный CSV из нуля строк.

## 4.2.0

### Добавлено

* **Чтение CSV через `Excel::open()`.** Теперь `open()` открывает и CSV-файлы, возвращая `Csv\CsvBook`
  — обычную книгу с одним листом и тем же API чтения `AbstractSheet` (режимы ключей, области чтения,
  `withHeader()`, `readColumns()`, ...), что у XLSX и XLS. Формат выбирается по сигнатуре (OLE2 → XLS,
  ZIP → XLSX, иначе CSV); опции передаются как `Excel::open($file, $options)`, а `['format' => 'csv']`
  форсирует CSV-ридер. Через `open()` ключи столбцов по умолчанию — буквы Excel, для паритета с XLSX.
  `openCsv()` не изменён и по-прежнему возвращает низкоуровневый движок `Csv\CsvReader` (он же доступен
  через `CsvBook::getReader()`). У CSV нет стилей, типизации чисел/дат, объединённых ячеек и картинок —
  соответствующие методы возвращают пустой результат, а не бросают исключение. См. [docs/ru/20-csv.md](docs/ru/20-csv.md).
* `Excel::isXlsx()` — проверка сигнатуры (`PK\x03\x04`), отличающая настоящий XLSX/ZIP-пакет от
  обычного текста, который `open()` затем читает как CSV.
* CSV: бинарный ввод (NUL-байт или высокая доля управляющих символов) теперь отсекается сразу понятной
  ошибкой «файл выглядит бинарным», а не падает где-то в глубине парсера. Текст UTF-16/UTF-32 не
  затрагивается. Новая опция `allow_binary` (`CsvOptions::setAllowBinary()`) отключает проверку.

### Изменено

* `Excel::open(string $file, $options = [])` принимает необязательный второй аргумент (BC-safe). Файл,
  который не является ни контейнером OLE2, ни ZIP, теперь читается как CSV, а не проталкивается в
  XLSX-ридер (где раньше падал) — исправление поведения для не-табличного ввода.
* ZIP, который не является XLSX (DOCX/PPTX или обычный архив), теперь падает с понятным сообщением
  «Not an XLSX workbook: the ZIP archive has no xl/workbook.xml» (с подсказкой про DOCX/PPTX), а не с
  загадочным «Internal file not found: xl/_rels/workbook.xml.rels».

### Исправлено

* CSV: пустой файл (или файл, длина которого кратна размеру буфера чтения) больше не вызывает
  PHP-warning и фантомную завершающую строку — теперь он корректно читается как ноль строк.
* CSV: `CsvReader::rewind()` теперь полностью сбрасывает состояние чтения, поэтому повторное чтение
  файла после частичного прохода больше не воспроизводит устаревший буфер.

## 4.1.0

### Исправлено

* Встроенные форматы дат (numFmtId 14–22, например код 14 — «краткая дата») теперь отображаются
  детерминированно. Раньше ридер перезаписывал их шаблоны из локали ICU всякий раз, когда было
  загружено `ext-intl`, поэтому один и тот же файл давал разные строки в зависимости от локали
  сервера и от наличия расширения ([#53](https://github.com/aVadim483/fast-excel-reader/issues/53)).
  Теперь эти коды резолвятся в фиксированные шаблоны независимо от окружения. Форматы, которые файл
  задаёт явно, не затрагиваются.

### Добавлено

* `useLocaleFormats(?string $locale = null)` — явное включение локале-зависимого отображения встроенных
  кодов дат (прежнее поведение, теперь осознанное). Передайте локаль для воспроизводимого вывода или
  ничего — тогда используется локаль процесса по умолчанию. Требуется `ext-intl`.

## 4.0.1

### Исправлено

* XLS теперь отдаёт текст формулы с ведущим `=`, как это всегда делает XLSX. Поле `f` ячейки с
  формулой имеет одинаковый вид независимо от формата файла, поэтому в коде больше не нужно
  отдельно обрабатывать XLS. Формулы, текст которых восстановить не удалось, по-прежнему возвращают
  `null`, а не `"="`.

## 4.0.0

### Добавлено

* **Чтение устаревшего формата XLS (Excel 97-2003, BIFF8).** `Excel::open()` теперь выбирает ридер по
  сигнатуре файла, поэтому XLSX и XLS открываются одинаково; расширение файла не учитывается.
  `Excel::openXls()` открывает книгу явно, а `Excel::isXls()` даёт саму проверку.
  См. `docs/ru/21-xls.md`.
  * Значения и типы, с определением дат по числовым форматам
  * Стили ячеек: шрифты, заливки, рамки, выравнивание, числовые форматы и цвета палитры
  * Текст формул, включая общие формулы
  * Встроенные изображения
  * Несколько листов, скрытые и «очень скрытые» листы, объединённые ячейки, размеры листа
  * Зашифрованные книги и файлы BIFF5/BIFF7 отклоняются с указанием, что именно не поддерживается
* `AbstractBook` и `AbstractSheet` — формат-независимая половина ридеров: области чтения, режимы
  ключей, флаги режима результата, генератор строк и все вспомогательные методы `read*`. У XLSX и XLS
  одна общая реализация всего публичного API чтения.
* `withHeader()` теперь принимает необязательный список имён столбцов:
  `withHeader(['name', 'birthday'])`. Строка заголовков по-прежнему пропускается, но имена берутся из
  списка, а не из её значений. Имена позиционные — первое достаётся первому столбцу области чтения, —
  поэтому буквы столбцов не нужны, и один и тот же вызов работает на листе, где данные начинаются не с
  `A1`. Более короткий список переименует только покрытые им столбцы. Поддерживается для XLSX, XLS и
  CSV. Вызов без аргумента работает как прежде. Именование согласовано с `writeHeader()` из
  родственного пакета fast-excel-writer.

### Исправлено

* `Sheet::readCellsWithStylesFrom()` возвращал голые значения ячеек вместо значений со стилями: он
  вызывал `readCells()` вместо `readCellsWithStyles()` и передавал ключ стиля в параметр типа bool.
* `Sheet::readCellsWithStyles($styleKey)` никогда не сужал результат до запрошенного свойства. Ключ
  искался во вложенной структуре стиля, где свойства лежат внутри своей группы, поэтому
  `'fill-color'` — пример из докблока самого метода — всегда возвращал полный стиль.
* Полные стили ячеек — `getCompleteStyleByIdx()`, `readCellsWithStyles()` и всё, что на них
  построено, — падали с `Call to undefined method DOMText::getAttribute()` на книгах, где
  `styles.xml` записан с отступами, а так пишут некоторые генераторы.

### Изменено

* **Чтение XLSX ускорено примерно в полтора раза.** Значения, типы и пик памяти не изменились.
* Методы, возвращавшие конкретный `Sheet`, теперь возвращают `AbstractSheet`, а fluent-сеттеры книги
  возвращают `AbstractBook`. Сами возвращаемые объекты не изменились, а наследник по-прежнему может
  сузить тип обратно, поэтому это затрагивает только явные объявления типов в вызывающем коде.

## 3.2.0

### Исправлено

Четыре дефекта, все — в методах, не покрытых тестами.

* `Sheet::readFirstRowCellsFrom()` всегда бросал `TypeError`: он передавал `$columnKeys` в
  `readFirstRowCells(?bool $styleIdxInclude)`, поэтому падал даже вызов со значениями по умолчанию.
  Поскольку результат ключуется адресом ячейки, ключи столбцов к нему неприменимы, и параметр убран
  по образцу `readCellsFrom()`. Сломать рабочий код невозможно: любой вызов старой сигнатуры бросал
  исключение.
* Ограничение по столбцам вместе с запросом числовых ключей столбцов возвращало одни `null`. При
  заданной области чтения шаблон строки ключевался буквой столбца, тогда как значения записывались под
  числовыми ключами, и значения затем отфильтровывались. Затрагивало `setReadArea()` и
  `setReadAreaColumns()` в сочетании с `KEYS_COL_ZERO_BASED` или `KEYS_COL_ONE_BASED`, а значит и с
  `KEYS_ZERO_BASED` и `KEYS_ONE_BASED`.
* `Sheet::rewind()` терял аргумент `$columnKeys`, хотя документирован как алиас `reset()`: в теле было
  присваивание параметру вместо его передачи.
* `Sheet::firstCol()` игнорировал границы столбцов области чтения и возвращал первую ячейку строки в
  том виде, как она хранится в файле. На `firstRow()` это не влияло.

### Добавлено

* Регрессионный набор тестов на путь чтения: характеризационные снапшоты по всем методам `read*`,
  полная матрица `KEYS_*`, флаги режима результата, области чтения, стили, даты, метаданные и
  вырожденные случаи, плюс отдельные тесты семантики генератора, областей чтения, объединённых ячеек и
  потокового расхода памяти. Режимы `RESULT_MODE_ROW`, `TRIM_STRINGS`,
  `TREAT_EMPTY_STRING_AS_EMPTY_CELL` и `KEYS_RELATIVE` до этого не были покрыты вовсе.

### Известные ограничения

* Файлы XLSX с префиксами пространств имён в тегах (`<x:row>`, `<x:c>`) читаются как пустые.
